# スタンプ作成フローのアーキテクチャ

## 1. 概要

このドキュメントは、「AI LINE Sticker Generator」アプリケーションにおけるスタンプ作成機能のアーキテクチャとデータフローを詳細に解説します。この機能は、ユーザーが選択または生成したキャラクターデザインを基に、AIを活用して複数のLINEスタンプを効率的に作成することを目的としています。

全体のフローは以下の主要なステップで構成されます：
1.  **キャラクター選択**: ユーザーはスタンプの元となるキャラクターを選択します。
2.  **生成設定**: スタンプの個数、テキストのスタイル、追加の指示などを設定します。
3.  **テキスト生成**: AIがキャラクター設定に基づいて、スタンプ用のセリフを複数提案します。
4.  **テキストの画像化**: 生成されたセリフをクライアントサイドで画像に変換します。
5.  **スタンプ画像生成**: AIが「キャラクター画像」と「テキスト画像」を組み合わせて、最終的なスタンプ画像を生成します。
6.  **修正とデバッグ**: ユーザーはAIが生成した画像をさらに微調整したり、生成時のデバッグ情報を確認したりできます。
7.  **ダウンロード**: 完成したスタンプを個別または一括でダウンロードします。

## 2. 主要コンポーネントと役割

スタンプ作成機能は、責務が明確に分離された複数のコンポーネントとサービスによって実現されています。

- **`components/StickerCreationTab.tsx`**:
  - スタンプ作成タブ全体のUIと状態管理を担当するメインコンポーネント。
  - キャラクターの選択、生成設定、API呼び出しのトリガー、生成されたスタンプの一覧表示など、すべてのユーザーインタラクションを処理します。

- **`components/StickerCard.tsx`**:
  - 個々のスタンプを表示・編集するためのカード型コンポーネント。
  - スタンプの現在の状態（生成中、完了、エラーなど）を視覚的に表示し、テキストの編集、修正モーダルの起動、デバッグ情報の表示、個別ダウンロードの機能を提供します。

- **`components/RevisionModal.tsx`**:
  - 既存のスタンプ画像をAIで対話的に修正するためのモーダルウィンドウ。
  - ユーザーからの修正指示を受け取り、リアルタイムでプレビューを更新し、変更を適用する機能を提供します。

- **`components/DebugModal.tsx`**:
  - スタンプ画像生成時に使用されたプロンプトと入力画像（キャラクター画像とテキスト画像）を表示するモーダルウィンドウ。開発者やパワーユーザーがAIの振る舞いを理解するのに役立ちます。

- **`services/geminiService.ts`**:
  - Gemini APIとの通信を担当するサービス。
  - `generateStickerTexts`, `generateStickerImage`, `reviseStickerImage`, `generateSuggestions` といった関数を通じて、具体的なAPIリクエストを抽象化します。

- **`services/aiConfigService.ts`**:
  - AIに送信するすべてのプロンプトテンプレートを管理するサービス。
  - `AITask.STICKER_TEXT` や `AITask.STICKER_IMAGE` など、タスクごとにプロンプトが定義されており、一元管理とユーザーによるカスタマイズを可能にしています。

- **`services/imageUtils.ts`**:
  - `createTextImage`関数を提供し、Canvas APIを利用してテキストを画像（Base64形式）に変換するユーティリティ。フォントスタイルや画像サイズなどのオプションをサポートします。

## 3. データフローとユーザーストーリー

ユーザーがスタンプを作成する際の具体的なフローを順を追って説明します。

### 3.1. キャラクターの選択

スタンプ作成は、まず元となるキャラクターを決定することから始まります。ユーザーには3つの選択肢があります。

1.  **3面図作成タブからの遷移**: `CharacterDesignTab` でキャラクターを生成後、「この画像でスタンプを作成する」ボタンを押すと、そのキャラクター(`CharacterDesign`オブジェクト)が`StickerCreationTab`に`initialDesign`として渡されます。
2.  **履歴からの選択**: サイドバーやタブ内の履歴リストから、過去に生成したキャラクターを選択できます。
3.  **カスタム画像のアップロード**: ユーザーはPCから任意のキャラクター画像をアップロードして、それをベースにスタンプを作成することも可能です。

### 3.2. 生成設定

キャラクターが選択されると、ユーザーは生成パネルで以下の項目を設定します。

- **スタンプ個数**: 4個から48個まで、4個単位で増減できます。
- **口調・雰囲気 & 文字の装飾**: 豊富な初期リストから選択します。さらに、「もっと読み込む」ボタンでAIに新しい提案（`generateSuggestions`）を動的に生成させ、選択肢を増やすことができます。
- **自由な指示**: デザインに関する追加の要望（例：「常に笑顔で」「キラキラしたエフェクトを追加」）をテキストエリアに入力できます。この指示はテキスト生成と画像生成の両方のプロンプトに反映されます。

### 3.3. テキストの一括生成

1.  ユーザーが「文字のデザインを生成」ボタンをクリックします。
2.  `StickerCreationTab`の`handleGenerateTexts`関数が実行されます。
3.  `geminiService.generateStickerTexts`が呼び出されます。この際、キャラクター設定、スタンプ個数、口調、装飾、そして自由な指示が引数として渡されます。
4.  サービスは`aiConfigService`から`AITask.STICKER_TEXT`のプロンプトを取得し、引数でテンプレートを埋めます。
5.  Gemini API (`gemini-2.5-flash`) にJSON形式のレスポンスを要求するリクエストが送信されます。
6.  APIから返されたテキストリストが`stickers`状態にセットされ、各`StickerCard`のテキストエリアに表示されます。

### 3.4. 画像の一括生成 (Client-side Pre-processing + AI Composition)

画像生成は、**クライアントサイドでのテキスト画像化**と**AIによる画像合成**という2段階の革新的なプロセスで行われます。

1.  ユーザーが「スタンプ画像を生成」ボタンをクリックすると、`handleGenerateImages`関数が実行されます。処理は**バッチ単位**（例: 4件ずつ）で行われ、APIへの過剰なリクエストを防ぎます。
2.  **ステップ1: テキストの画像化 (Client-side)**
    - 各スタンプのテキストに対し、`services/imageUtils.createTextImage`が呼び出されます。
    - この関数は、設定された「文字の装飾」スタイルと、設定画面でユーザーが指定した「テキスト画像の高さ」を基に、HTML Canvasを使ってテキストを描画した画像（Base64形式）を生成します。
3.  **ステップ2: 画像の合成 (AI)**
    - `geminiService.generateStickerImage`が、**2つの画像**（ベースとなる「キャラクター画像」と、ステップ1で生成された「テキスト画像」）を引数として呼び出されます。
    - サービスは`AITask.STICKER_IMAGE`のプロンプトを使用します。このプロンプトは、AIに対して「2つの画像を自然に組み合わせて1枚のLINEスタンプを完成させてください」と明確に指示します。
    - 生成に使用されたプロンプトと入力画像2枚は、`Sticker`オブジェクトの`generationPayload`プロパティに保存されます。
    - `gemini-2.5-flash-image-preview`モデルがリクエストを処理し、完成したスタンプ画像データ(Base64)とファイル名を返します。

### 3.5. 個別の修正とデバッグ

- **テキスト編集**: ユーザーは各`StickerCard`のテキストエリアで、AIが生成したテキストをいつでも手動で編集できます。
- **AIによる画像修正**:
  - 「AIで修正」ボタンから`RevisionModal`を開き、自然言語で修正を指示できます。このプロセスは、完成したスタンプ画像を基に再生成を行うため、元の画像合成フローとは独立しています。
- **デバッグ**:
  - 各カードのデバッグアイコンをクリックすると`DebugModal`が開きます。
  - モーダルには、そのスタンプの生成に使用された最終的な**プロンプト全文**と、入力として渡された**キャラクター画像**および**テキスト画像**が表示され、AIの挙動を詳細に分析できます。

### 3.6. ダウンロード

- **個別ダウンロード**: 各カードのダウンロードアイコンから、そのスタンプ画像を直接ダウンロードできます。
- **一括ダウンロード**: 「一括ダウンロード」ボタンで、完成したすべてのスタンプを一つのZIPファイルにまとめてダウンロードします。

## 4. 技術的な特徴とこだわり

- **ハイブリッド画像生成アプローチ**: テキスト描画というAIが苦手としがちなタスクを、高精度なクライアントサイドのCanvas APIで処理し、AIには得意なキャラクターのポージングや画像合成に集中させることで、テキストの品質を保証しつつ、全体的なスタンプのクオリティを飛躍的に向上させました。
- **非同期バッチ処理**: 画像生成は時間のかかる処理ですが、リクエストを小さなバッチに分割して順次処理することで、API制限を回避し、アプリケーションの安定性を保っています。
- **プロンプトの抽象化とカスタマイズ**: `aiConfigService`でプロンプトを一元管理し、設定画面からユーザーがカスタマイズ可能にすることで、高い柔軟性とメンテナンス性を実現しています。
- **透過的なデバッグ機能**: `generationPayload`に生成コンテキストを保存し、それを可視化するUIを提供することで、AIのブラックボックス性を低減し、ユーザーがより意図した結果を得るための試行錯誤を支援します。
